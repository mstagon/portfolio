01 / OVERVIEW

어떤 프로젝트인가요?

여러 앱에 미니게임과 광고 보상 경험을 제공하는 플랫폼입니다. 게임과 결과 화면을 공통 웹 플랫폼으로 옮기고, Flutter SDK에는 세션과 호스트 광고 연동을 남기는 구조 전환을 맡았습니다. 게임 제작 및 서버 개발은 팀과 협업했습니다.

  1. 01게임 공통 규약
  2. 02웹의 진행 · 결과 화면
  3. 03SDK 광고 · 서버 정산

02 / ENGINEERING

구현과 판단

01

게임 콘텐츠와 SDK 배포를 분리

게임은 시작·정지·재개·종료 규약을 따르고, 제출·광고 진입·결과·랭킹은 공통 플랫폼이 맡도록 나눴습니다. 게임 추가를 네이티브 SDK 릴리스와 분리하면서 팀이 만든 콘텐츠를 같은 흐름에 연결했습니다.

02

구 SDK와 새 웹이 같은 판을 두 번 처리하지 않게

웹이 처리하는 모드, 기존 SDK가 처리하는 모드, 세션이 없어 진행할 수 없는 모드를 구분했습니다. 이미 제출된 판은 광고만 재시도하고 점수 제출을 반복하지 않도록 진행 상태를 나눴습니다.

03

광고 · 백그라운드 · 재진입이 겹치는 순간

정지 사유를 집합으로 관리해 마지막 사유가 사라져야 게임을 재개했습니다. 문서 시작과 SPA 경로 변경을 구분하고, 재진입 후 도착한 이전 세션의 콜백이 새 게임에 적용되지 않게 했습니다.

04

여러 매체사의 환경을 하나의 계약으로

채널·테스트/상용 환경·세션을 런타임에 전달하고, 호스트가 실제 지원하는 광고 기능만 웹에 알렸습니다. 광고 어댑터를 SDK 코어 밖에 두고 최종 보상 검증과 적립은 서버의 책임으로 유지했습니다.

04 / OUTCOME

결과와 범위

웹 중심 구조로 전환하며 게임 콘텐츠의 변경과 네이티브 SDK 배포를 분리했습니다. 위 내용은 2026년 8월 전환 당시 맡은 웹·SDK 구조와 연동 계약을 중심으로 정리했습니다.
